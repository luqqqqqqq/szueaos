# 环境与调试笔记

可直接执行的命令集中在 [开发与验证](../development.md)。环境准备见 [快速开始](../getting-started.md)，本页补充工具选择与阅读源码时的几个约定。

## 工具各自负责什么

- **NASM**：将汇编源码转成机器码；`-f bin` 输出平坦二进制，`-l` 生成汇编清单。
- **Bochs**：模拟处理器、BIOS 和磁盘控制器，适合观察引导阶段与寄存器状态。
- **VHD 扇区写入工具**：把二进制放到磁盘文件的指定扇区。运行已有样例时无需写盘。
- **二进制查看器**：检查引导签名、扇区内容与写入位置。

已有固定大小 VHD 时无需再安装其他虚拟机软件。若自行新建镜像，需同时核对格式、容量、磁盘几何及 Bochs 配置。

## 阅读汇编源码

| 语法或约定 | 在当前工程中的作用 |
| --- | --- |
| `org 0x7c00` | 指定 MBR 的汇编地址基准，本身不负责加载文件 |
| `section core vstart=0x900` | 指定 Loader 区段的运行地址基准 |
| `[bits 32]` | 告诉汇编器生成 32 位指令编码，CPU 模式仍由控制寄存器和跳转改变 |
| `times 510-($-$$) db 0` | 将 MBR 填充到签名前的 510 字节 |
| `db 0x55,0xaa` | 引导扇区末尾签名 |
| `jmp $` | 在当前位置循环停留 |

## 调试时先核对

1. Bochs 是否从工作 VHD 的 LBA 0 启动。
2. MBR 是否停在键盘等待处；源码中的等待是预期行为。
3. Loader 是否写入 LBA 1，文件是否仍不超过 512 字节。
4. 磁盘读取目标地址和 Loader 的 `vstart` 是否同为 `0x0900`。
5. 修改后的 `.lst` 是否与本次生成的二进制配套。
